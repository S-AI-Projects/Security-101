## Local scenario-rubric simulation

The [offline Python example](./applied-labs/r34-t014/example.py) is a small fictional exercise tied to [8.3 Responsible AI: “How can I ensure my AI system is both secure and ethical?”](./8.3%20Responsible%20AI.md). It checks that an answer has an asset, threat, control, and residual-risk field, records a state after each checking step, and flags differing declared threat/control categories for human review. The checker verifies structure and the provided categories only; a person must judge the scenario explanation and whether the control truly addresses the threat.

Requires Python 3 and the standard library only. From the repository root, run:

```bash
python3 ./applied-labs/r34-t014/example.py
```

The normal fictional fixture is: asset `Fictional customer-support training transcripts`; threat `Personal information could be exposed from the training transcripts.`; control `Remove direct identifiers and limit dataset access to approved staff because these steps reduce exposure of transcript data.`; residual risk `Indirect identifiers may remain, and an authorized user could still misuse an accessible copy.` Its expected output ends with:

```text
Intermediate states: received -> normalized -> completeness -> control_review -> final
Missing fields: none
Control review: matched (none)
Rubric result: PASS
```

Two other local mock fixtures demonstrate rubric outcomes. Run `python3 ./applied-labs/r34-t014/example.py --scenario boundary` to omit the asset; expected result is `Missing fields: asset`, `Rubric result: FAIL`, and exit status 1. Run `python3 ./applied-labs/r34-t014/example.py --scenario failure` for a fictional model-evasion threat paired with an unrelated data-encryption control; expected result is `Control review: review (...)` and `Rubric result: REVIEW`. The checker does not infer meaning from prose or claim anything about a real AI system, hardware, cloud service, or model performance.

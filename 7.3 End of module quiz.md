## Local scenario-rubric simulation

The [offline Python example](./applied-labs/r34-t015/example.py) uses fictional data-loss-prevention scenarios tied to [7.1 “What is data loss prevention (DLP)?”](./7.1%20Data%20security%20key%20concepts.md). Each answer has an asset, threat, control, and residual-risk field. It checks completeness and compares declared threat/control categories; human review must judge whether the written explanation and proposed control actually make sense.

Requires Python 3 and the standard library only. From the repository root, run:

```bash
python3 ./applied-labs/r34-t015/example.py
```

The normal fictional fixture uses asset `Fictional customer invoice files`, threat `A restricted invoice could be sent to an unauthorized external recipient.`, control `Inspect outbound email for restricted invoice content and warn or block unapproved external sharing.`, and residual risk `A renamed or otherwise unrecognized attachment could evade inspection.` Expected result:

```text
Scenario: normal (local fictional mock)
Asset: Fictional customer invoice files
Threat: A restricted invoice could be sent to an unauthorized external recipient.
Control: Inspect outbound email for restricted invoice content and warn or block unapproved external sharing.
Residual risk: A renamed or otherwise unrecognized attachment could evade inspection.
Missing fields: none
Control review: matched (none)
Rubric result: PASS
```

Run `python3 ./applied-labs/r34-t015/example.py --scenario boundary` to omit the asset; it reports `Missing fields: asset` and `Rubric result: FAIL` (exit status 1). Run `python3 ./applied-labs/r34-t015/example.py --scenario failure` to pair an email-exfiltration threat with a backup-restore control; it reports `Control review: review (...)` and `Rubric result: REVIEW`. The examples and categories are a local simulation, not an actual DLP tool or assessment of any real system, service, hardware, or model.

## Applied Lab: Application Security Scenario Checker (R34-T034)

### Objective

Create a local scenario checker that evaluates fictional application security scenarios using asset, threat, control, and residual-risk fields.

### Lesson references

- 5.1 AppSec key concepts: Input Validation, Output Encoding, Authentication and Authorization, Data Protection.
- 5.2 AppSec key capabilities: SAST, DAST, Dependency Scanning, and Secure Code Review.

### Run the simulation

From the repository root, run:

```bash
python3 applied-labs/r34-t034/example.py
```

Expected output:

```text
APPSEC-01: PASS - Control matches the named threat
APPSEC-02: FAIL - Missing required fields: asset
APPSEC-03: REVIEW - Control may be unrelated to the named threat

Simulation complete.
Scenarios checked: 3
```

### Run automated tests

```bash
python3 -m unittest discover -s applied-labs/r34-t034 -v
```

Expected result: 5 tests pass.

### Run expected-versus-actual comparison

```bash
python3 applied-labs/r34-t034/compare_results.py
```

Expected final output:

```text
COMPARISON PASSED
```

The comparison checker exits with a nonzero status if an actual result does not match its expected result.

### Intermediate-state invariant

The checker records intermediate states for each scenario. The final output status and reason must match the last recorded state.

An automated test verifies this invariant.

### Simulation limitations

This lab uses fictional local JSON fixtures and deterministic Python keyword rules. It does not connect to a real application, security scanner, external model, paid provider, GPU, or physical device.

The keyword checker is a mock structural consistency check. A human reviewer must judge whether the explanations and controls are genuinely appropriate.

The original 5.3 quiz file contains a heading and Microsoft Forms link, but no quiz questions. These scenarios are therefore based on the R34-T034 task requirements and lessons 5.1 and 5.2, not extracted quiz questions.

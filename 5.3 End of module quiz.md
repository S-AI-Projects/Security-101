## Worked scenario-rubric example

This is a fictional, local simulation of the evidence a learner might provide
for an application-security scenario. Each scenario contains an `asset`,
`threat`, `control`, and `residual_risk`, tied to a named lesson section such
as input validation or secure APIs.

- A complete relevant example passes the structural checker.
- A scenario without an asset fails.
- A control unrelated to the named threat is flagged for human review.

The automated checker verifies stated structure and a small threat/control
mapping only. Human review is required to judge the explanation, accuracy,
and residual-risk rationale.

Prerequisite: Python 3; no external package or service is required. From the
repository root:

```bash
python3 ./applied-labs/r34-t023/example.py --scenario normal
python3 -m unittest discover -s ./applied-labs/r34-t023 -p "test_*.py"
```

The normal fixture prints `result=pass` for a customer-profile web form under
the malformed-input threat. The complete fixture comparison and automated
limits are documented in
[the R34-T023 applied lab](./applied-labs/r34-t023/README.md).
